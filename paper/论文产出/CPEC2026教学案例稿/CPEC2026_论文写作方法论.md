## 1. 《实验技术与管理》风格基线（已查官方投稿须知，直接固化）
- **文稿构成**：文题、作者、单位、摘要、关键词、分类号、首页地脚注释、正文、参考文献、英文部分。
- **首页地脚**：收稿日期；基金项目（项目类别+编号）；作者简介（第一作者生年-、性别、籍贯、学位、职称、职务、研究方向、Email）；通信作者（学生一作→导师，含生年/职称/研究方向/Email）。
- **层次标题**：1 / 1.1 / 1.1.1；图1、表2、文献[3]、式(4)。
- **文题**：≤20 汉字，准确简明。
- **中文摘要**：**结构式四要素（目的/方法/结果/结论）**，**第三人称**，**200–250 字**，**禁用「本文/笔者」**，缩略语先说明。
- **英文摘要**：与中文对应，文题≤100 字符（首词不用冠词），摘要≥100 词、主动语态、避免第一人称。
- **关键词**：5–8 个（优先《汉语主题词表》）。
- **图表**：表格用**三线表**、数值个位对齐、小数 3 位；线图≥1200dpi 或 **PDF 矢量**（你用 pgfplots/TikZ 已达标）。
- **参考文献**：**顺序编码制 + GB/T 7714-2015**（你已做，保留）；期刊格式：作者.题名[J].刊名,年,卷(期):起止页。
- **字数**：≥5000 字（你 16 页远超）。
- 你已具备的普刊字段：中图分类号 TP393.08;TP18、文献标志码 A、英文摘要、作者简介——与上式一致，保留并**补首页地脚（基金/通信作者）**。

### Phase 1 — 证据锁定 + 三处必改（半天，可并行）
- 1.1 把论文每个数字与 `backend/gnn/eval_full_results.json` / `eval_results.json` 逐项核对，生成「数字—源」映射表（**文档不可信，已多次验证**）。
- 1.2 落实三处必改（改动点+风险先讲清）：
  - **A. HAN F1 口径统一**：以 10-seed 聚合 **0.9154±0.1214（hard）/ 1.0000±0.0000（clean）** 为权威值（见 eval_full_results.json）。摘要/结论里的「0.93」对齐为「约 0.92」或注明「10 种子均值 0.9154」；代码单 seed 0.9466 注明为代表性单点。风险：仅文字，不影响实验。
  - **B. 双通道增益诚实化**（最关键的诚实边界）：
    - 真实聚合：exp1（cross=0.2）hard 增益 **mean≈0.013±0.080**（1 正 2 负，近似为 0）；exp2（更强结构扰动）hard 增益 **mean≈0.090±0.110**（4/10 正、0 负，去文本通道 F1 由 1.0 跌到 0.91）。
    - 结论：**文本补强是场景依赖的——结构扰动足够强时才显著**。
    - 处置：①摘要/引言/结论去掉「文本通道在结构受扰时补强」的**绝对化断言**，改为「提供文本通道补强的设计能力，其增益随结构扰动强度而显现」；②在 §4.2 补一段「诚实标注+双通道消融」，给出上述真实数字（exp1≈0.013±0.080 不显著；exp2≈0.090±0.110 显著）。风险：涉及摘要/方法/结论多处措辞，需同步改避免前后矛盾。
  - **C. 格式字段补齐**：补首页地脚（基金编号待填、通信作者吴老师）、确认结构式摘要四要素、三线表、矢量图。

### Phase 2 — 分阶段改写（核心 3–4 天，按 8/15 倒排）
- 2.1 **重写摘要为结构式四要素**（目的/方法/结果/结论），第三人称，200–250 字，禁「本文」；英文摘要对应、≥100 词、主动语态。
- 2.2 **引言重锚定**到「新工科 / AI 赋能实验教学」语境：背景=反诈实战教学缺口 → 贡献=可落地的反诈实训系统+实验教学体系。
- 2.3 **方法/实验保持技术深度**（这是差异化卖点），但每节补一句「对教学的支撑」（如：反思闭环可作实训中「系统自纠错」教学案例；双通道融合可作「多源证据融合」教学示例）。
- 2.4 **新增/强化「实验教学价值」段落**（对应征文主题）：系统作为可复现实验平台、复杂工程问题实践、学生实践能力培养、课程思政/新工科契合点。
- 2.5 **结论+展望**保持诚实边界（合成≠真实、增量边界、不构成真实验证通过、GNN 非全设定占优）。
- 每改完一类即 `xelatex` 编译校验（0 undefined / 0 warning）。

## 3. 红线（不可破）
- 合成 ≠ 真实验证；增量边界量化；不构成「真实警务数据验证通过」；GNN 非一切设定占优——**一律原样保留，不得为顺口而淡化**。
- 所有论断须有 `eval_full_results.json` 等真实产物支撑；文档/旧记忆与代码冲突时以代码与真实产物为准。
- 不编造实验、不虚构真实数据端到端结果。
