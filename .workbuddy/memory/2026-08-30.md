## ⚠️ 实测发现：AI 问答与 RAG 当前都是坏的（起后端实测确认）
用户问"RAG 是不是没用上、AI 问答起不了效果"——**结论：现象上用户说对了，但机理和我之前"RAG 已接好"的说法不冲突：接线有，运行时全挂。**

### 故障1：LLM 全链路 404（根因：9 处硬编码模型名）
- `agents/chat_agent.py`(5处:261/479/755/930/1050)、`agents/analyst_agent.py`(2处:205/281)、`agents/gang_reviewer.py`(2处:162/276) 全部写死 `model="deepseek-chat"`，**不读 settings.DEEPSEEK_MODEL**。
- key.env 里 BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1、MODEL=qwen3.8-flash、DISABLE_CLOUD_LLM=0，**配置本身没问题**（实测该 key + qwen3.8-flash / qwen-plus / qwen-turbo 都能正常返回）。
- 结果：向 DashScope 端点要 deepseek-chat → 404 model_not_found → ReAct/意图识别/回答生成三步全失败 → 前端只看到兜底话术"抱歉，我暂时无法处理您的请求"。
- 影响面：AI 对话问答 + 案情分析智能体 + 团伙复核(LLM 模式)。也就是说换 key 之后这些功能就一直没真正生效。

### 故障2：RAG 检索 100% 抛异常（根因：向量维度不匹配）
- 实测：入库 chunk 向量 **768**（`rag/knowledge_base.py:206 _hash_embedding(dim=768)` 降级产物），查询向量 **1024**（BGE-large 真模型，core/embedding.py:37）。
- `kb.search` 点积 numpy 抛 `ValueError: shapes (1024,) and (768,) not aligned` → 一次都检索不出来。知识库有 10 篇反诈文档（data/knowledge_base/knowledge_base.json，json 里只存 content 不存向量，启动时现算）。
- 即：播种/入库时 embedding_model 为 None 走了 hash 降级，查询时却拿到了真 BGE。

### 待修（已向用户报方案，等拍板）
- 修1：9 处硬编码改 `settings.DEEPSEEK_MODEL`（建议顺手抽成 core/llm_client 的统一取模函数，避免再漏）。低风险但碰 3 个 agent 文件。
