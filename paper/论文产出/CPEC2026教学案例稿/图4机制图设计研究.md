## 二、可借鉴的 5 条共性经验

1. **画"流程"而非"结构"**：用箭头把"输入→处理→输出"串起来，让评审一眼看懂系统怎么运作。
   纯分层架构图（如我们的 fig_arch）信息量低，机制图信息量高。
2. **学生是流程起点也是终点**：谢鑫图5、向尕图1 都从"学生"出发，最后回到"学生能力/作品"。
   我们的图必须把"学生操作"放在首尾，把"系统响应"放中间。
3. **三元角色分工要画出**：刘莞玲（师-机-生）、谢鑫（学生/教师/智能体）都在图里区分角色。
   我们的图可区分【学生】【FraudLens 系统】【评价/审计】三类。
4. **用线型/底色区分"系统自动" vs "学生介入"**：张金用红色标"指南给出内容"；
   我们可把"人机协同决策点"用高亮框/粗边标出，凸显教学交互。
5. **caption 写清"示意图/机制，非算法展开"**：避免过度技术化引发"这是算法论文"误读，
   与我们已定的"本文是教学案例而非算法论文"定调一致。

## 三、图4 设计草案

**图名**：图4 学生实验流程与系统响应机制（示意图）

**布局**：横向四栏 + 底部闭环带（总宽约 5.8in，高约 3.0in）

```
┌──────────────────────────────────────────────────────────────────────────┐
│ ① 学生操作区（输入）                     ② FraudLens 系统响应（处理）        │
│   · 选择 Lab（1-4）                       预处理：案情清洗/字段对齐          │
│   · 加载案情 / AMLSim 数据集      ──▶     BGE 语义嵌入 + 异构图构建(HAN)     │
│   · 设定研判参数(阈值/种子)                LangGraph StateGraph 闭环：        │
│                                            plan→preprocess→analyze(图NN)    │
│                                            →cluster(串并案)→reflect(反思降级)│
│                                            ↓ 输出：候选团伙/账户 + 研判报告   │
│ ③ 人机协同决策点（学生介入，高亮框）       ④ 闭环反馈带（底部贯穿）          │
│   · 人工规则 vs AI 建议对比（Lab1/2）      审计日志 → 加权评价量表           │
│   · 冻卡阈值调参 + 伦理权衡（Lab3）      → 思政/伦理映射 → 回流"研-训-评"   │
│   · 失败场景反思（Lab4）                                               │
└──────────────────────────────────────────────────────────────────────────┘
```

**画法要点**：
- ①→② 用实线箭头；② 内部 5 个 StateGraph 节点用带箭头的圆角框串联（仿张金技术路线）；
- ③ 决策点用**粗边/浅色高亮框**，标注"学生介入"，对应 Lab1-4 的核心任务；
- ④ 底部用虚线带连接"审计→评价→思政映射→研训评"，呼应 fig_mode；
- 全程不出现公式、不画网络拓扑细节，只到"机制节点"层级。

## 三-补、吸收谢鑫/厉旭杰节点后的精炼版（推荐采用）

- 用 3 种底色区分泳道：学生(浅蓝)/系统(浅灰)/决策(浅黄高亮)；

**建议 caption**：
> 图4 学生实验流程与系统响应机制（示意图）：学生以四环节实验链为单位向系统输入案情与参数，系统经预处理、语义嵌入与图构建形成研判对象，由 LangGraph 多智能体状态图完成"规划—预处理—分析—聚类—反思"，输出候选结果供学生进行人机协同决策；全程审计日志与加权评价量表支撑"研—训—评"闭环。图中处理节点为机制示意，算法细节以系统说明文档为准。
