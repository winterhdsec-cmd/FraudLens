## 一、现状诊断

### 1.1 后端（扎实，核心能力过硬）

- **编排器**：`orchestrator.py` 基于 LangGraph StateGraph 实现 plan → preprocess → analyze → cluster → reflect 条件闭环（不是手写顺序编排器）
- **GNN**：HAN/GraphSAGE 已真实跑通，有三层实验验证（合成基线 + AMLSim 扩线 + Elliptic 边界）
- **智能体**：analyst、cluster、chat、reflect、specialist、abnormal、demo 共 7 个 Agent
- **异步**：Celery 任务队列支撑案例自动分析管道
- **接口**：FastAPI 对外暴露 `/agent-analyze`、`/api/cases`、`/api/gangs` 等 REST 接口

### 1.2 前端（问题集中，是比赛短板）

| 问题 | 严重程度 | 说明 |
|---|---|---|
| App.vue 28KB 单体 | 高 | SPA 视图切换全在一个文件里，不可维护 |
| 登录页统计硬编码 | 高 | "77+案件、12团伙、92%准确率、12s响应"——假数字，评委看到直接扣分 |
| 视图数量少 | 中 | 仅 CaseDetail/Chat/CapitalFlow/Alerts/Admin/Api 共 6 个，缺数据看板 |
| 组件复用度低 | 中 | 仅 NetworkGraph/MiniNetworkGraph/ShowcaseView 等 5 个组件 |
| UI 风格业余 | 中 | 登录页 emoji，无统一设计语言 |
| 无数据看板 | 中 | 比赛演示最重要的页面不存在 |

### 1.3 核心矛盾

> 后端能力足够支撑比赛，但**前端不会展示** + **没有数据看板** + **缺少将技术转译为故事的叙事能力**。

## 四、无真实数据下的说服力策略

这是比赛中最关键的难题：**没有真实警务数据，如何让评委相信你的系统不是玩具？**

分四个层次。

### 4.1 用合成数据讲"真实故事"

核心转变：不讲"我们造了100条假数据"，讲"我们还原了一个典型诈骗团伙的完整作案过程"。

**案例叙事模板**（以刷单诈骗为例）：

> 2024年3月，某市警方接到8名受害者报案，均被"点赞返利"诱导下载App并大额转账。受害者分布在3个省份，话术高度相似（"完成3联单即可提现""数据修复费"）。FraudLens从8份报案笔录中提取结构化案情，构建异构图（8案件-12账户-5手机号-1城市），经双通道HAN聚类识别为一个由3层级账户组成的洗钱团伙，冻卡建议置信度0.85。与传统人工串并案相比，系统发现了一条在3份笔录中均未被提及的多跳资金关联。

**为什么这比"我们有77个案件"有说服力？**
评委看的不是数量，是"你的系统到底解决了什么问题，怎么解决的"。

### 4.2 用公开基准构建"可验证的能力基线"

论文实验数据直接转化为比赛材料：

> "我们用3个不同数据源做了能力基线测试——合成数据 F1 达到 0.91，AMLSim 公开基准上 k-core 方法可恢复到 0.71，Elliptic 上验证了方法的适用边界。所有实验脚本和结果随仓库开源，评委可自行复现。"

比"有77个案件"分量重得多。

### 4.3 设计"数据接入框架"而非"假数据填充"

在代码中实现 `data_loader.py`，定义标准化案例导入接口：

```python
class CaseImporter:
    """通用案件导入框架。
    
    当前支持：
    - CSV 导入（行=案件，列=字段）
    - 手工录入（Web 表单）
    - API 对接（预留，需签约公安内网接口）
    """
    def from_csv(self, path: str) -> List[Case]: ...
    def from_manual(self, form: dict) -> Case: ...
    def from_api(self, endpoint: str) -> List[Case]: ...  # 预留
```

比赛时的话术：

> "考虑到真实警务数据涉及公民隐私和案件保密，我们设计了标准化数据接入框架。当前用合成数据和公开基准验证核心算法，框架已预留公安内网API对接接口。一旦与公安机关达成数据合作，即可零代码接入真实数据。"

**这比"我们没数据"或"我们造了假数据"都好。**

### 4.4 降级演示路径

准备两套演示模式，比赛时按需切换：

| 模式 | 数据源 | 适用场景 |
|---|---|---|
| Demo 模式 | 系统内置的 3-5 个"原型案例" | 现场演示，展示从案情到判决的完整链路 |
| 实验模式 | 合成数据 10 seeds + AMLSim | 答辩时展示可复现性，佐证能力边界 |

## 五、比赛叙事逻辑

### 5.1 一句话核心主张

> "反诈研判中，基层民警面对海量案件难以串并，传统 AI 方案依赖标注数据难以落地。FraudLens 以合成数据+公开基准为支撑，在 LangGraph 多智能体反思编排下实现'案情分析→AI 辅助串并案→冻卡决策→边界反思'的完整闭环，所有能力可复现验证，架构已预留真实数据接口。"

### 5.2 三个核心论点

**论点一：问题真实而迫切**

公安反诈实战中，"串并案靠人脑记、靠Excel查"是普遍现状。一个团伙的8个案件可能分散在3个省份的5个不同派出所，传统串并需要数周，AI辅助研判是刚需。

**论点二：方案可行且可复现**

FraudLens两级研判闭环（案件级串并案 + 账户级扩线），合成数据 F1 0.91，公开基准 F1 0.71，所有实验一键复现。不依赖不可验证的"内测数据"。

**论点三：工程可落地**

docker-compose 一键部署，FastAPI 后端 + Vue3 前端，RBAC 鉴权 + 双表审计 + 数据不出域，预留公安内网对接接口。不是概念原型，是可运行系统。

### 5.3 与竞品的差异化

| 维度 | 传统反诈系统 | FraudLens |
|---|---|---|
| 技术路线 | 规则匹配 / 关键词 | 异构 GNN + 多智能体反思编排 |
| 数据依赖 | 需要大量标注训练集 | 无监督预训练，少量标注即可校准 |
| 可验证性 | 依赖内测数据 | 公开基准可复现 |
| 可解释性 | 黑箱 | 冻卡置信度门控 + 权重说明 |
| 部署 | 通常需要商业合作 | docker-compose 开源部署 |
