## 第四轮：内置 Redis（方案 C）——告别 Docker Desktop

用户诉求："Redis 不能直接集成到项目内吗？必须 Docker Desktop 吗？" → 结论：Redis 是 C/S 独立进程，pip 包只是客户端；但可把 **Windows 便携版二进制随仓分发 + 后端启动时自动拉起**。

### 实现
- `backend/vendor/redis/`：tporadowski Redis 5.0.14.1（GitHub Releases zip，2.5MB 必需文件，BSD 可分发），git 已纳管（`?? backend/vendor/`）
- 新模块 `core/redis_embedded.py`：`ensure_embedded_redis()` 幂等引导——socket 裸探测 `PING→PONG` 三分支（redis 复用 / open 非 Redis 占用跳过 / free 则 Popen 拉起）；`atexit` 注册清理（redis-py `SHUTDOWN SAVE` 落盘，不依赖 redis-cli.exe）；仅 Windows + 本机 REDIS_HOST + 无哨兵时生效，任何异常只 WARNING 不阻断
- `main.py` 在 `load_dotenv` 之后、中间件之前调引导；`config.py` 加 `REDIS_AUTOSTART`/`REDIS_EMBEDDED_MAXMEM`；本机 key.env 置 `REDIS_AUTOSTART=1`；`.gitignore` 排除 `vendor/redis/runtime/`（dump.rdb/日志不入库）
- `redis_pool.py` 两处逻辑修正：① `get_redis_pool()` 原来"localhost 一律视为未配置"→ 永久内存兜底，改为 `ping_ok` 探测式；② 内置模式下收紧 connect 超时至 0.5s（消除全链路 2s×N 超时雪崩）

### 两个关键兼容坑（本轮最贵的教训）
1. **Windows 版 redis-server.exe 命令行不吃 `--save "300 10"`** → `Invalid argument: Not enough parameters`，进程秒死、日志为空难排查。去掉 `--save`（默认周期 save + 退出 SHUTDOWN SAVE 已够）。手动前台跑一次二进制立刻暴露根因。
2. **redis-py 8.x 默认发 `HELLO 3`（RESP3 握手），Redis 5.0.14 无 HELLO 命令** → `unknown command HELLO`，所有连接全挂。根治：`_resp2_kw()` 探测性 helper（inspect 签名，redis-py<5 自动跳过）给 `redis_pool.py` 全部 4 个客户端构造点 + `redis_embedded` shutdown 加 `protocol=2`——对任意版本 Redis 服务端通用（6/7 也支持 RESP2）。

### 效果实测
- 后端启动：**84s → 1~6s**（原来全链路反复吃 Redis TCP 超时）
- dashboard 冷算 **~53s → 0.015s**：`SHUTDOWN SAVE` → dump.rdb → 新进程 Redis 启动自加载，`persist_probe` key 跨两次重启存活实锤
- 冒烟回归全绿：gangs 0.062s / review-results 0.031s / dashboard 命中 0.000s / 限流 Redis 路径连发 6 次正常
- 生产端不变：docker-compose.yml 的 redis:7-alpine 照旧（开发演示机=内置，服务器=容器）

### 专利/答辩可用表述
"分级缓存自适应：外部 Redis → 内置便携 Redis（探测式自动拉起）→ 进程内存兜底，任一层缺失不中断研判业务；SHUTDOWN SAVE + RDB 快照实现缓存跨重启常驻"——对应代码即 redis_embedded.py + redis_pool.py 降级链。
